# v0.6.0 — Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export the currently-filtered history as CSV, a printable HTML report, and a formatted PDF — grouped by activity with sum-then-rounded totals and amounts — with an option to emit one file per activity for client invoicing.

**Architecture:** Three pure builders turn `(sessions, totals, meta)` into a `String`/bytes: `CsvBuilder`, `HtmlReportBuilder`, `PdfReportBuilder`. An `ExportService` gathers data from `HistoryRepository`, picks scope (combined vs per-activity, D6), and writes files to a user-chosen location. Export screen reuses History's active filter.

**Tech Stack:** `pdf` + `printing`, `path_provider`/`file_picker`, plus prior stack. No new network deps.

**Spec:** `docs/superpowers/specs/2026-10-31-local-time-tracker-design.md`

## Global Constraints

- Export scope = the active History filter (activity + date range) (D6).
- Grouped by activity; totals are sum-then-round (D4); amount when rate set.
- CSV carries exact per-session durations; rounding appears on totals/summary rows.
- Fully local file writing; no upload. Set `pubspec.yaml` `version: 0.6.0+6`.

## Review Focus

- **Notes containing commas / quotes / newlines in CSV:** properly escaped (RFC 4180 quoting), not corrupting columns. → test in Task 2.
- **Activity without a rate in reports:** amount column blank, grand total still correct. → test in Tasks 2–3.
- **Empty export (filter matches nothing):** produces a valid empty-but-well-formed file, not a crash. → test in Task 2.
- **Per-activity file naming collisions / unsafe characters:** sanitize activity name into a safe filename, de-duplicate. → test in Task 4.
- **Rounded hours vs exact in the summary:** the report's hours and amounts must both derive from the rounded total, never the exact seconds. → test in Task 3.
