# v0.4.0 — Platform Shell Seam + Mac Menu Bar & Hotkey Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Introduce the `PlatformShell` capability seam (resolved via DI) so screens request capabilities instead of branching per platform, then land the Mac implementation: a menu-bar presence with a live-ticking title and a Start/Stop popover, plus a system-wide global hotkey that opens a Spotlight-style activity picker which starts a timer without raising the main window.

**Architecture:** `PlatformShell` is a platform-free interface exposing capabilities (`registerQuickStart`, `setMenuBarTitle`, `showPicker`). A `NoopPlatformShell` is the default (used on iOS until v0.5 and in tests); `MacPlatformShell` wires `tray_manager` (status item + title), `window_manager` (popover + main window show/hide), and a global-hotkey package. The shell is chosen once at startup and injected; screens and core stay branch-free. The quick-start picker reuses the `StartCoordinator` (v0.3) so starting behaves identically everywhere.

**Tech Stack:** tray_manager, window_manager, a macOS global-hotkey package (candidate `hotkey_manager`), plus the v0.3 stack. Mac-only packages live behind the shell seam.

**Spec:** `docs/superpowers/specs/2026-11-02-cross-platform-redesign-design.md`

## Global Constraints

- Shell branching happens at a **single seam** (`PlatformShell` via DI); screens and the platform-free core never import platform-UI packages. (Spec: Platforms and architecture)
- Quick-start **always opens a chooser**; it never blind-starts the last activity. The Mac hotkey picker is type-to-filter and starts without raising the main window. (Spec: Quick-start)
- iOS has no menu bar — the Mac menu-bar/hotkey code must be unreachable on iOS (behind the seam). (Spec: Platform shell)
- Closing the Mac main window hides it (app stays in the menu bar); it does not quit.
- Set `pubspec.yaml` `version: 0.4.0+4`.

## Review Focus

- **Hotkey pressed while a timer already runs:** the picker still opens and a pick routes through the D1 switch confirm (via `StartCoordinator`), never a silent switch. → test in Task 2 + manual in Task 6.
- **Menu-bar title while idle:** shows a short idle label, never a stale time from a stopped session. → test in Task 3.
- **Main window closed, then the hotkey picker used, then window reopened:** engine state intact (same providers), timer still ticking in the title. → manual check in Task 6.
- **A pending resume decision (D2) at launch:** must surface on a visible window, not be lost behind a hidden window or the popover. → Task 6 Step 5.
- **Hotkey package failing to register (already taken / permission):** app still runs and the menu bar still works; it surfaces a one-time note, does not crash. → **validation flag**, manual in Task 1 / Task 5.
