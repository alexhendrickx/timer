# v0.5.0 — iPhone Quick-Start & Widgets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the iOS side of the platform-shell seam: the iPhone Action button (and a Siri Shortcut) opens the app straight onto the focus-cards picker, and lock-/home-screen WidgetKit widgets show per-activity tiles for one-tap start from outside the app.

**Architecture:** An `IosPlatformShell` implements the `PlatformShell` seam from v0.4. It has no menu bar (`hasMenuBar == false`); its quick-start capability deep-links the running app onto the picker route. The Action button, Siri Shortcut, and widgets are served by a native iOS extension (App Intents + WidgetKit) that reads the shared activities from the app group and, when launched, hands an `activityId` (or "open picker") to Flutter over a deep link / method channel. Flutter then routes to the picker or calls `StartCoordinator`. The DB stays in the iOS app container; the widget reads a lightweight snapshot via the app group.

**Tech Stack:** `go_router` deep links, a platform `MethodChannel`, a native iOS WidgetKit + App Intents extension, an app group. v0.4 stack otherwise. No new Dart network deps.

**Spec:** `docs/superpowers/specs/2026-11-02-cross-platform-redesign-design.md`

## Global Constraints

- Quick-start **always opens a chooser**; from outside, a widget tile may carry a target `activityId`, but it routes through `StartCoordinator` (D1 confirm honored). (Spec: Quick-start)
- iOS has no menu bar; the Mac-only code from v0.4 must stay unreachable. The iOS DB lives in the app container — **no folder picker on iOS**. (Spec: Platform shell, Data model)
- The platform-free core and screens are unchanged; only `IosPlatformShell` + native extension are added. (Spec: Platforms and architecture)
- Set `pubspec.yaml` `version: 0.5.0+5`.

## Review Focus

- **App launched from a widget tile while a different activity runs:** routes through the D1 switch confirm, never a silent switch. → manual in Task 5.
- **App cold-launched from the Action button (process not running):** reaches the picker after init, not a blank first frame. → manual in Task 5.
- **Widget shown with no activities / stale snapshot:** renders an empty tile and an "open app" affordance, never a crash. → manual in Task 4.
- **Deep-link payload with an unknown/archived `activityId`:** falls back to opening the picker rather than starting a bad session. → test in Task 3.
- **iOS backgrounding mid-session:** quick-start re-entry does not spawn a second timer; D2 resume still governs a stale open session. → manual in Task 5.
