# v0.9.0 — Supabase Local-First Sync & Sign in with Apple Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep Alex's two devices (iPhone + Mac) in agreement by syncing `activities` and `sessions` through his own Supabase project behind Sign in with Apple — a background, debounced, last-write-wins layer that never blocks the fully-local flow and works on both iOS and macOS. Without signing in, the app stays purely local and unchanged.

**Architecture:** Local SQLite stays the source of truth. Each syncable row gains a stable `uid` (UUID — the cross-device identity, since autoincrement ids differ per device), an `updatedAt` (already present) and a `deletedAt` soft-delete flag, plus a local-only `dirty` flag marking rows needing push. A platform-free `SyncEngine` pushes dirty rows up and pulls remote changes down, resolving per-row with last-write-wins on `updatedAt` and honoring soft-delete; it is driven by a debounced change signal, by reconnect, and by sign-in. An `AuthService` wraps Sign in with Apple → a Supabase session (the `user_id`). Supabase tables mirror the local schema with RLS `user_id = auth.uid()`. The live `TimerEngine` is untouched — local remains authoritative for the running count.

**Tech Stack:** `supabase_flutter`, `sign_in_with_apple`, `uuid`, `connectivity_plus` (reconnect signal), drift migrations, the v0.8 stack. Networking is limited to the user's own Supabase project — no other cloud.

**Spec:** `docs/superpowers/specs/2026-11-02-cross-platform-redesign-design.md`

## Global Constraints

- **Local-first:** every write hits local SQLite first and is queued; losing network never blocks start/stop; sign-in is optional and the app is fully usable without it. (Spec: Sync, Offline)
- Only `activities` and `sessions` sync, scoped to the signed-in `user_id`; RLS `user_id = auth.uid()` guarantees a user only reads/writes their own rows. (Spec: Sync — What syncs)
- **Conflict resolution = last-write-wins per row on `updatedAt`** (single user, no merge UI). A closed session is immutable except its `note` (also LWW). (Spec: Sync — Conflict resolution)
- **Soft-delete via `deletedAt`** so archive/D7 hard-delete propagates and a deleted row is not resurrected on the next pull. (Spec: Sync — Deletes/archive)
- The running session may sync its `lastSeenAt` as it ticks, but local stays authoritative for the live count. (Spec: Sync — Direction & timing)
- Set `pubspec.yaml` `version: 0.9.0+9`.

## Review Focus

- **Offline the whole session, then reconnect:** all local writes made offline push on reconnect; nothing is lost or blocked meanwhile. → test in Task 6 (queue drain) + manual in Task 7.
- **Same row edited on both devices while offline:** on sync the higher `updatedAt` wins on both; the loser is overwritten, no duplicate row (matched by `uid`). → test in Task 5 (resolver) + Task 6.
- **Delete on device A vs. edit on device B:** `deletedAt` wins when it is the later timestamp; the row is not resurrected by B's pull. → test in Task 5.
- **Signed out / never signed in:** zero network calls; the app behaves exactly as v0.8. → test in Task 4 + manual in Task 7.
- **Sign in with Apple on macOS:** must complete and yield the same `user_id` as iOS. → **validation flag**, manual in Task 4.
- **Pull of a remote row with a `uid` not present locally:** inserted locally with a fresh local id; a second pull does not duplicate it (idempotent on `uid`). → test in Task 6.

- Produces: `class SyncEngine`:
  - `bool get enabled` — true only when `AuthService.isSignedIn`.
  - `void notifyLocalChange()` — debounced trigger (e.g. 2s) that schedules a `syncNow()`.
  - `Future<void> syncNow()` — push all `dirty` rows (clear `dirty` on success), then pull remote rows changed since the last pull, applying `ConflictResolver.resolve` per `uid` (insert remote-only rows idempotently, apply soft-deletes). No-op when `!enabled`.
  - `void onReconnect()` — triggers `syncNow()`.
