# v0.1.0 — Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A running macOS Flutter app with datewatch-style theming, a drift SQLite database opened at a user-chosen folder, and empty Home + Settings screens.

**Architecture:** Flutter desktop (macOS target only). Feature-first layout mirroring datewatch (`lib/core/{theme,routing,services,utils}`, `lib/feature/*`). `provider` for state, `go_router` for navigation. Local SQLite via `drift`; the DB file lives in a folder chosen by the user and persisted with `shared_preferences`.

**Tech Stack:** Flutter/Dart (sdk ^3.10), drift + sqlite3_flutter_libs, shared_preferences, path_provider, file_picker, go_router, provider.

**Spec:** `docs/superpowers/specs/2026-10-31-local-time-tracker-design.md`

## Global Constraints

- macOS desktop target only in v1; keep other platform folders unmodified. (Spec: Non-goals)
- Fully local: **no** network/Firebase/http packages ever added. (Spec: Constraints, Anti-goals)
- Never lose the exact recorded time; rounding is a view only. (Spec: Anti-goals)
- Mirror datewatch structure and token-based theming (`AppColors` + `buildAppTheme()`). (Spec: The "how")
- App version in `pubspec.yaml` as `version: x.y.z+build`; this plan sets `0.1.0+1`. (Spec: Versioning)
- Carry datewatch's Karpathy principles into this repo's `CLAUDE.md`. (Spec: Coding principles)

## Review Focus

- **Chosen data folder is missing/unwritable on next launch** (moved/ejected drive): app should fall back to the default folder and surface a message, not crash. → test in Task 4.
- **No data folder chosen yet (first run):** must default to `~/Documents/Timer` and create it. → test in Task 4.
- **Rounding boundary exactly on the half-hour** (900s, 2700s): define round-half-up behavior deterministically. → test in Task 2.
- **Zero duration / negative inputs** to rounding and formatting helpers: return `0` / `"0:00"`, never throw. → test in Task 2.
- **DB file already exists** from a prior version: opening must migrate/open cleanly, not recreate. → covered by drift schemaVersion in Task 3.

### Task 2: Duration rounding + formatting utils

**Files:**
- Create: `lib/core/utils/duration_utils.dart`
- Test: `test/core/duration_utils_test.dart`

**Interfaces:**
- Produces:
  - `int roundToHalfHourSeconds(int totalSeconds)` — rounds to nearest 1800s; ties (900, 2700, …) round **up**; input ≤ 0 → 0.
  - `String formatHms(int seconds)` — `H:MM:SS` for the live timer; ≤ 0 → `"0:00:00"`.
  - `String formatHoursMinutes(int seconds)` — `H:MM` (e.g. `9:30`); ≤ 0 → `"0:00"`.

- [ ] **Step 1: Write the failing tests**

```dart
test('rounds a 9h12m day down to 9:00', () {
  expect(roundToHalfHourSeconds(33120), 32400); // 9h00
});
test('rounds a 9h22m day up to 9:30', () {
  expect(roundToHalfHourSeconds(33720), 34200); // 9h30
});
test('ties round up (15 min -> 30 min)', () {
  expect(roundToHalfHourSeconds(900), 1800);
});
test('zero and negative clamp to zero', () {
  expect(roundToHalfHourSeconds(0), 0);
  expect(roundToHalfHourSeconds(-5), 0);
});
test('formatHoursMinutes of 34200s is 9:30', () {
  expect(formatHoursMinutes(34200), '9:30');
});
test('formatHms of 8073s is 2:14:33', () {
  expect(formatHms(8073), '2:14:33');
});
```

- [ ] **Step 2: Run tests to verify they fail**

Run: `flutter test test/core/duration_utils_test.dart`
Expected: FAIL (functions undefined).

- [ ] **Step 3: Implement the three functions in `duration_utils.dart`**

`roundToHalfHourSeconds`: `(seconds / 1800).round() * 1800` after clamping negatives to 0 — note Dart's `double.round()` rounds half away from zero, giving ties-up.
