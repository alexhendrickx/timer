# v0.3.0 — Menu Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A top-right menu-bar icon showing live elapsed + current activity, a frameless popover to Start/Stop and add a quick note, and a way to open the full window.

**Architecture:** `tray_manager` owns the status-item icon and title (updated from `TimerEngine` each second). Clicking it toggles a small frameless `window_manager` window (the popover) anchored near the tray. The popover is a Flutter route reusing the tracker widgets. The main window is shown/hidden rather than destroyed.

**Tech Stack:** tray_manager, window_manager (added this version), plus v0.2 stack.

**Spec:** `docs/superpowers/specs/2026-10-31-local-time-tracker-design.md`

## Global Constraints

- macOS only; the tray title shows live `H:MM:SS` + activity name while running, idle text otherwise.
- Closing the main window hides it (app keeps running in the menu bar), does not quit.
- Set `pubspec.yaml` `version: 0.3.0+3`.

## Review Focus

- **Tray title while idle (no timer):** shows a short idle label (e.g. app name or "—"), never a stale time. → test in Task 2.
- **Rapid Start/Stop from the popover:** reflects engine state without desync from the main window. → manual check Step in Task 4.
- **Main window closed then reopened from tray:** state intact (same providers), timer still running. → manual check in Task 4.
- **App launch with a resume decision pending (v0.2 D2):** resume dialog must surface on the window, not be lost behind a hidden window. → Task 4 Step 5.
