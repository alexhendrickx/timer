# v0.7.0 — History Drill-Down & Reports Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A top-down history browser — today's day list → a week bar chart → a month calendar heatmap — plus a Reports screen showing per-activity totals as a ring/pie chart with the exact figures and amounts listed beside it, all filterable by activity and date range.

**Architecture:** A pure `TotalsCalculator` does sum-then-round (D4) and `amount = roundedHours × hourlyRate`; a pure `HistoryAggregator` buckets sessions into per-day (week) and per-day-of-month (heatmap) series. A `HistoryRepository` runs the filtered drift queries and feeds both. Presentation is three drill-down views (day/week/month) plus a Reports view that reuses the totals. All calculation is platform-free and unit-tested; charts follow the `dataviz` guidance.

**Tech Stack:** drift, provider, go_router, `duration_utils` (v0.1). Charts are drawn with Flutter `CustomPainter`/widgets per `dataviz`; no chart package required.

**Spec:** `docs/superpowers/specs/2026-11-02-cross-platform-redesign-design.md`

## Global Constraints

- Totals are **sum-then-round** (D4) via `roundToNearest(totalSeconds, stepSeconds)`, default step **900s (15 min)**; per-session rows always show exact time. The stored `durationSeconds` is never rounded. (Spec: Rounding, Anti-goals)
- Amounts appear only for activities with an `hourlyRate`; `amount = roundedHours × rate` on the rounded group total, with a grand total. (Spec: Reports)
- A session is attributed to its **start day** (D5) for all filtering, grouping, and bucketing. (Spec: D5)
- Navigation is top-down: today (day list) → week → month; nothing recorded is ever discarded. (Spec: History)
- Set `pubspec.yaml` `version: 0.7.0+7`.

## Review Focus

- **Group summing to an exact rounding boundary** (e.g. 900s, 2700s): rounds predictably (ties-up). → test in Task 2.
- **Activity with no rate:** totals show time only; amount omitted (not €0); grand total still correct. → test in Task 2.
- **Date-range filter on a midnight-crossing session:** matched by start day only (D5). → test in Task 3.
- **Empty history / empty filter / a week or month with no sessions:** empty state, totals 0, chart renders an all-zero series without crashing. → test in Tasks 2–3.
- **A day with multiple activities in the heatmap/bar:** the day's shade/height reflects the summed exact seconds for that day across activities. → test in Task 3.

**Interfaces:**
- Produces:
  - `int roundToNearest(int totalSeconds, [int stepSeconds = 900])` in `duration_utils.dart` — `(totalSeconds / stepSeconds).round() * stepSeconds`; input ≤ 0 → 0; ties round up. (The v0.1 `roundToHalfHourSeconds` stays; this generalizes it with a 15-min default. Settings will make the step configurable in v0.8.)
  - `class ActivityTotal { int activityId; String name; int exactSeconds; int roundedSeconds; double? amount; }`
  - `ActivityTotal TotalsCalculator.forGroup(List<Session> sessions, Activity activity, {int stepSeconds = 900})` — `roundedSeconds = roundToNearest(sum(exact), stepSeconds)`; `amount = (roundedSeconds/3600) * hourlyRate` when a rate is set, else null.
