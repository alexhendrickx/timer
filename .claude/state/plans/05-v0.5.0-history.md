# v0.5.0 — History & Totals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A History screen listing past sessions, filterable by activity and date range, showing exact per-session time and sum-then-rounded totals per activity with optional amounts; edit notes, re-tag, and archive/delete.

**Architecture:** A `HistoryRepository` runs filtered queries and computes grouped totals. A `TotalsCalculator` (pure) does sum-then-round (D4) and amount = roundedHours × hourlyRate. The History screen binds to the repository; row actions edit note / re-tag / delete; activity delete routes through archive per D7.

**Tech Stack:** drift, provider, Flutter; `duration_utils` (v0.1).

**Spec:** `docs/superpowers/specs/2026-10-31-local-time-tracker-design.md`

## Global Constraints

- Totals are **sum-then-round** to the half-hour (D4); per-session rows show exact time.
- Amount shown only when the activity has an `hourlyRate`; amount = roundedHours × rate.
- Deleting an activity with sessions is forbidden → archive (D7). Individual sessions may be deleted.
- A session is attributed to its **start day** (D5) for date filtering/grouping.
- Set `pubspec.yaml` `version: 0.5.0+5`.

## Review Focus

- **Group with sessions summing to an exact half-hour boundary:** rounds predictably (reuse v0.1 ties-up). → test in Task 2.
- **Activity with no rate:** totals show time only, amount omitted (not €0). → test in Task 2.
- **Date-range filter on a midnight-crossing session:** matched by start day only (D5). → test in Task 2.
- **Attempt to delete an activity that has sessions:** blocked with an archive prompt, no FK violation. → test in Task 3.
- **Empty history / empty filter result:** shows an empty state, totals = 0, no crash. → test in Task 2.
