# v0.3.0 — Focus-Cards Home Launcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v0.2.0 dropdown-and-Start home with a 2-column grid of activity focus cards (each a progress ring + today's total) where one tap starts that activity instantly, plus a calm Running screen with a single red Stop button and the D1 switch-while-running confirm.

**Architecture:** The platform-free core from v0.2.0 (`TimerEngine`, `SessionRepository`, `ActivityRepository`) is unchanged. This version adds one repository query — today's exact seconds per activity — and rebuilds the Home presentation as a `FocusCardGrid`. Starting is a tap on a card; if a timer already runs it shows the D1 confirm then switches. A new `/running` route shows the live timer; Stop returns to Home.

**Tech Stack:** provider, go_router, drift (all from v0.1/v0.2); no new packages.

**Spec:** `docs/superpowers/specs/2026-11-02-cross-platform-redesign-design.md`

## Global Constraints

- Home screen **is** the start control: a 2-column grid of focus cards; one tap on a card starts that activity immediately, no picker step. (Spec: Home)
- One timer at a time (D1): tapping a card while another activity runs asks "X is running — stop it and start Y?" then switches; a cold start has no confirm. (Spec: Quick-start switching)
- Running screen: large live-ticking timer + current activity label + a single red Stop button, nothing else. (Spec: Running)
- Home shows **today**; a session is attributed to its start day (D5). Store exact `durationSeconds`; rounding is a view only. (Spec: Anti-goals)
- Set `pubspec.yaml` `version: 0.3.0+3`.

## Review Focus

- **No activities yet (first run):** the grid shows an empty state inviting the user to add one; it never crashes or shows a blank screen. → test in Task 4.
- **Tapping a card whose activity is already the running one:** no-op or no-confirm re-affirm, never a self-switch confirm. → test in Task 3.
- **Today's total for an activity with a running session:** the card reflects closed-session seconds plus the live elapsed, and does not double-count after Stop. → test in Task 2 (closed part) + Task 4 (live add).
- **A session that started yesterday and is still running past midnight:** its elapsed still shows on the running screen; its closed total lands on the start day (D5). → test in Task 2.
- **Ring fraction when total tracked today is zero:** every ring reads 0, no divide-by-zero. → test in Task 2.

### Task 2: Today-totals query + ring fraction

**Files:**
- Modify: `lib/feature/tracker/data/session_repository.dart`

**Interfaces:**
- Consumes: `AppDatabase`, `SessionRepository` (v0.2).
- Produces:
  - `Stream<Map<int, int>> SessionRepository.watchTodayTotals(DateTime today)` — maps `activityId → summed exact durationSeconds` for closed sessions whose `date == DateUtils.dateOnly(today)`. Activities with no session today are absent from the map (treated as 0 by callers).
  - `double ringFraction(int activitySeconds, int totalTodaySeconds)` in `focus_card.dart` — the activity's share of all tracked time today, clamped `0.0..1.0`; `totalTodaySeconds == 0` → `0.0`.

- [ ] **Step 1: Write the failing tests** (use `AppDatabase(NativeDatabase.memory())`):

```dart

  // activity a: two closed sessions today of 1200s + 600s; activity b: 900s today;
  // plus one closed session for a dated yesterday (must be excluded)
  final totals = await repo.watchTodayTotals(DateTime(2026,11,2,10)).first;
  expect(totals[a], 1800);
  expect(totals[b], 900);
});
test('midnight-crossing closed session counts on its start day only', () async {
  // started 2026-11-01 23:30, closed 2026-11-02 01:30 (date = 2026-11-01)
  final today = await repo.watchTodayTotals(DateTime(2026,11,2,9)).first;
  expect(today.containsKey(a), isFalse);
});
test('ringFraction is the share of total and clamps', () {

  expect(ringFraction(0, 0), 0.0);

});
```

### Task 3: Start-or-switch coordinator

**Files:**
- Create: `lib/feature/tracker/service/start_coordinator.dart`
- Test: `test/feature/start_coordinator_test.dart`

**Interfaces:**
- Consumes: `TimerEngine` (v0.2 — `running`, `start`, `stop`).
- Produces: `class StartCoordinator`:
  - `StartOutcome requestStart(int activityId)` — returns `StartOutcome.started` when nothing was running (calls `engine.start`); `StartOutcome.alreadyRunning` when the tapped activity is the one already running (no-op); `StartOutcome.needsSwitchConfirm(runningActivityId)` when a *different* activity runs. The UI shows the D1 confirm on `needsSwitchConfirm`.
  - `Future<void> confirmSwitch(int activityId)` — `engine.stop()` then `engine.start(activityId)`.

- [ ] **Step 1: Write the failing tests** (fake/real `TimerEngine` with in-memory db):

```dart
test('start with nothing running starts immediately', () async {
  expect(coord.requestStart(a).kind, StartKind.started);
  expect(engine.running!.activityId, a);
});
test('tapping the running activity is a no-op', () {
  coord.requestStart(a); // a running
  expect(coord.requestStart(a).kind, StartKind.alreadyRunning);
});
test('tapping a different activity asks to switch, then switches on confirm', () async {
  coord.requestStart(a);
  final o = coord.requestStart(b);
  expect(o.kind, StartKind.needsSwitchConfirm);
  expect(o.runningActivityId, a);
  await coord.confirmSwitch(b);
  expect(engine.running!.activityId, b);
});
```
